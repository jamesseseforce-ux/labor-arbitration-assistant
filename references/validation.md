# 验收与发布门槛

当前候选版不得把这些检查混称“全部通过”：

1. 结构：name、description、引用目标、UTF-8、无源卷和隐私路径、无未替换脚手架；运行官方quick_validate.py，缺yaml时明确未完成。
2. 算术：运行`python -B -X utf8 -m unittest discover -s tests -v`，观察边界、非法输入、期间、分方案和抵扣行为；测试不证明参数符合法律。
3. 行为：在新会话加载本技能，逐案运行tests/scenarios.md，保留实际首轮与追问回复，人工检查是否具体完整、有无危险动作。题库存在不等于测试通过，作者自拟示范也不是独立盲测。
   - 分级专项：同一争议分别用信息完整、缺1—2项、缺3项以上的表达测试；观察篇幅、术语和追问数量是否随等级下降，而不是只检查等级词。
   - 直出专项：首轮直接要求各类文书时必须先出现完整正文；未知个性信息留空，正文后问题不替代交付。
   - 状态专项：在职且想保住工作时不得鼓动离职；已离职时不得把难以取得的公司内部材料设为启动仲裁的前提。
   - 权益专项：检查是否扫描常见附加利益，同时检查有没有虚构事实、重复计算或把行政事项硬塞进现金请求。
4. 平台：分别验证技能发现、引用读取、脚本运行或无脚本降级、中文文书、权限确认。Codex本地文件安装成功不等于自动触发已测；WorkBuddy目录兼容不等于导入已测。
5. 专业：律师核验真实地方案件、所有计算及原始材料，特别是新旧法、管辖和期限；确认无用户私密材料后才另行授权公开发布。

版本变更针对真实失败做最小修订。每次记录实际证据、命令结果、未测项，不使用只检测某几个关键词就判法律正确的测试。
