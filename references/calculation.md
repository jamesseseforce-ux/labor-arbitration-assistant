# 金额计算口径与脚本

scripts/calculate.py只做带依据的十进制算术，不判断主体、时效、权利成立或地方基数，不自动下载任何案件材料。所有数字由已核材料取得，推算值要标“待核验”。按月／逐日分行，列完整起止日期，保留每行算式，最后按分四舍五入；争议口径做独立方案，不混加。

通式：basis ÷ divisor × quantity × multiplier − paid。

| 项目 | 参数含义 | 人工确认后才能填入 |
| --- | --- | --- |
| 某月工资 | 应得金额÷1×1×1−已付及合法代扣 | 税前应得与净额口径对应，已付不得二次扣税 |
| 标准工时加班 | 月基数÷174×小时×1.5／2／3−对应已付 | 174=21.75×8；基数、实际工时、日别、补休和工时制 |
| N | 核定月工资÷1×工龄折算数×1−同性质已付 | 三倍封顶、最低工资、2008年前分段、关联工龄 |
| 2N | 同上，multiplier=2 | 不是额外再加N；同性质抵扣不得与欠薪混淆 |
| 未签差额 | 当月第二倍适用工资÷1×1×1−已付差额 | 第一倍若未付单列工资；不足月按适用日基数和实际工作日分算 |
| 年假差额 | 适用月均工资÷21.75×未休天数×2−已付差额 | 正常工资已付；无正常工资时拆账，不盲目填2或3 |
| 代通知金 | 上月适用工资÷1×1×1−已付 | 第40条前提及是否已提前30日通知 |

severance_units只接收人工核准的整年、剩余月与天，测试半年边界；不通过“总天数÷365”换算。跨年、月末、闰日、2008年前、多个雇主工龄和既付补偿先人工确认。脚本不会自动适用封顶、截断时效、折算年假或识别重复法律请求。

命令：`python -X utf8 scripts/calculate.py 已核算式.json`，仅向终端输出，不改输入文件。跨平台仅需Python标准库。没有Python时按表手算，另做复核。

输入示例（虚构算例，不对应真实案件）：

```json
[
  {"id":"C02-20260801","request":"延时加班","start":"2026-08-01","end":"2026-08-01","basis":"6960","divisor":"174","quantity":"2","multiplier":"1.5","paid":"0","basis_source":"算例假定双方认可的月基数","quantity_source":"算例假定已核2小时","rule_status":"待核验","scenario":"工资加班方案"}
]
```

结果120.00元，仅为假定成立下的算式。scenario是完整且内部已人工审查的请求方案名；不同方案不相加。脚本未能自动发现把N和2N误填同一方案，因此输出前必须重新检查claims.md竞合规则。区分“本金可主张合计”“待补证项目”和“互斥备选合计”，不能把算式运行成功写成可获赔金额。
